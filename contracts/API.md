# SIH26090 Artisan Platform - API Integration Guide

This document outlines the STRICT API CONTRACT for integrating the Flutter mobile app with the Node.js backend. This document was generated by auditing the actual current backend source code.

## 1. Environment Configuration

The backend is exposed over HTTP.

**Base URLs:**
- Local Developer Machine: `http://localhost:3000`
- Android Emulator: `http://10.0.2.2:3000`
- iOS Simulator: `http://127.0.0.1:3000`
- Physical Device (LAN): `http://<YOUR_LOCAL_IP>:3000` (e.g., `http://192.168.1.5:3000`)

```dart
// Example Configuration
class ApiConfig {
  static const String baseUrl = 'http://10.0.2.2:3000';
}
```

## 2. Authentication Flow

**Identity derivations:**
The backend extracts your identity (`userId`, `role`, `artisanId`, `buyerId`) strictly from the validated JWT token payload on every protected endpoint. 
**DO NOT** send your `userId` or `artisanId` from local storage when calling protected endpoints unless explicitly asked for in the payload. 

**Authentication Type:** JWT Bearer Token

### MSG91 OTP Widget Integration

1. Flutter displays the MSG91 OTP Widget.
2. User authenticates via the widget.
3. MSG91 provides an `access-token` directly to the Flutter app.
4. Flutter calls `POST /api/auth/msg91/verify` with this token.
5. The Node backend securely validates the token, finds/creates the user, and returns an application JWT.
6. Flutter stores the JWT and attaches it as a `Bearer` token to all authenticated requests.

*(Never expose `.env` values or MSG91 Authkeys in the Flutter app).*

## 3. API Reference

### 3.1 Authentication

#### POST /api/auth/msg91/verify
**Purpose:** Verify the MSG91 widget token and retrieve the application JWT.
**Authentication:** Not required
**Role:** Public

**Headers:**
```http
Content-Type: application/json
```

**Request Body:**
```json
{
  "accessToken": "<MSG91_ACCESS_TOKEN>",
  "role": "ARTISAN" 
}
```
*Note: `role` is optional and only used if this is a brand new user registering. Values: "ARTISAN" or "BUYER".*

**Success Response (200 OK):**
```json
{
  "token": "eyJhbGciOiJIUzI1NiIs...",
  "isNewUser": false,
  "redirect": "/artisan/home"
}
```

**Error Responses:**
- `400 Bad Request`: "Access token is required" or validation errors.
- `401 Unauthorized`: MSG91 token invalid.

**Flutter Note:** Save the `token` securely (e.g., using `flutter_secure_storage`).

#### GET /api/auth/me
**Purpose:** Retrieve the currently logged-in user and their profile data.
**Authentication:** Required
**Role:** Any authenticated user

**Headers:**
```http
Authorization: Bearer <JWT>
```

**Success Response (200 OK):**
```json
{
  "success": true,
  "data": {
    "user": {
      "id": "c138f828-580d-45db-b003-8e7c10b2df7e",
      "mobileNumber": "919999999999",
      "role": "ARTISAN",
      "status": "ACTIVE",
      "createdAt": "2026-09-04T12:00:00.000Z",
      "updatedAt": "2026-09-04T12:00:00.000Z"
    },
    "artisanProfile": {
      "id": "e492f231-180a-45ba-c123-9f8d10c2df8f",
      "userId": "c138f828-580d-45db-b003-8e7c10b2df7e",
      "name": "Artisan Name",
      "craftType": "Woodworking",
      "experience": 5,
      "address": "123 Craft Lane",
      "state": "Odisha",
      "district": "Khordha",
      "pincode": "751001"
    }
  }
}
```

**Error Responses:**
- `401 Unauthorized`: "Not authorized, no token" or "Not authorized, token failed".
- `404 Not Found`: "User not found".

### 3.3 AI Catalogue APIs

#### POST /api/v1/ai/catalogue/generate
**Purpose:** Generates a structured product catalogue from raw text.
**Authentication:** Required
**Role:** Any authenticated user

**Request Body:**
```json
{
  "text": "This is a wooden chair made of teak wood."
}
```

**Success Response (200 OK):**
```json
{
  "productName": {
    "en": "Teak Wood Chair",
    "hi": "सागौन की लकड़ी की कुर्सी"
  },
  "description": {
    "en": "A beautiful wooden chair made of premium teak wood.",
    "hi": "प्रीमियम सागौन की लकड़ी से बनी एक सुंदर कुर्सी।"
  },
  "category": "Furniture",
  "material": "Teak Wood",
  "tags": ["wooden", "chair", "furniture", "teak"]
}
```

#### POST /api/v1/ai/speech-to-text
**Purpose:** Transcribes a voice recording into text.
**Authentication:** Required
**Role:** Any authenticated user
**Headers:** `Content-Type: multipart/form-data`
**Body:** form-data field `audio` (File limit 25MB). Supported formats: m4a, mp3, wav, webm, ogg, mp4, mpeg, mpga, flac.

**Success Response (200 OK):**
```json
{
  "success": true,
  "data": {
    "text": "This is a wooden chair...",
    "language": "hi"
  }
}
```

#### POST /api/v1/ai/catalogue/generate-from-audio
**Purpose:** Performs transcription and catalogue generation in a single call.
**Authentication:** Required
**Role:** Any authenticated user
**Headers:** `Content-Type: multipart/form-data`
**Body:** form-data field `audio`.

**Success Response (200 OK):**
```json
{
  "success": true,
  "data": {
    "transcript": "This is a wooden chair...",
    "language": "hi",
    "catalogue": {
      "productName": { "en": "Teak Wood Chair", "hi": "सागौन की लकड़ी की कुर्सी" },
      "description": { "en": "A beautiful wooden chair...", "hi": "..." },
      "category": "Furniture",
      "material": "Teak Wood",
      "tags": ["wooden", "chair"]
    }
  }
}
```

### 3.4 Products

#### POST /api/v1/products
**Purpose:** Create a new product. (Forces status to DRAFT).
**Authentication:** Required
**Role:** ARTISAN

**Request Body:**
```json
{
  "productName": {
    "en": "Wooden Table",
    "hi": "लकड़ी की मेज"
  },
  "category": "Furniture",
  "material": "Wood",
  "description": {
    "en": "A sturdy wooden table.",

  },
  "tags": ["table", "wood"],
  "imageUrl": "https://example.com/image.jpg"
}
```

**Success Response (201 Created):**
```json
{
  "success": true,
  "data": {
    "id": "uuid",
    "artisanId": "uuid",
    "productName": { "en": "Wooden Table", "hi": "लकड़ी की मेज" },

    "createdAt": "2026-09-04T12:00:00.000Z",
    "updatedAt": "2026-09-04T12:00:00.000Z"
  }
}
```

#### GET /api/v1/products/my
**Purpose:** List all products owned by the artisan.
**Authentication:** Required
**Role:** ARTISAN

**Success Response (200 OK):** Array of product objects.

#### GET /api/v1/products/:id
**Purpose:** Retrieve a specific product.
**Authentication:** Required
**Role:** ARTISAN (Must own)

#### PUT /api/v1/products/:id
**Purpose:** Update an existing product.
**Authentication:** Required
**Role:** ARTISAN (Must own product)
**Request Body:** Same fields as POST, all optional.

#### PATCH /api/v1/products/:id/publish
**Purpose:** Set product status to PUBLISHED.
**Authentication:** Required
**Role:** ARTISAN (Must own)

#### PATCH /api/v1/products/:id/unpublish
**Purpose:** Set product status to DRAFT.
**Authentication:** Required
**Role:** ARTISAN (Must own)

#### DELETE /api/v1/products/:id
**Purpose:** Delete a product.
**Authentication:** Required
**Role:** ARTISAN (Must own)

### 3.6 Orders & Fulfillment

Orders enforce strict status flow: `PENDING` -> `ACCEPTED` / `PARTIALLY_ACCEPTED` -> `FULFILLING` -> `COMPLETED`.

#### POST /api/v1/orders
**Purpose:** Create a new order.
**Authentication:** Required
**Role:** BUYER

**Request Body:**
```json
{
  "artisanId": "uuid",
  "productId": "uuid",
  "requestedQty": 100,
  "unitPrice": 250.0,
  "requiredBy": "2026-10-25T00:00:00.000Z"
}
```
*(Note: `productId`, `unitPrice`, and `requiredBy` are optional)*

**Success Response (201 Created):**
```json
{
  "success": true,
  "data": {
    "id": "uuid",
    "buyerId": "uuid",
    "artisanId": "uuid",
    "productId": "uuid",
    "requestedQty": 100,
    "unitPrice": "250.00",
    "totalAmount": "25000.00",
    "requiredBy": "2026-10-25T00:00:00.000Z",
    "status": "PENDING",
    "createdAt": "2026-09-04T12:00:00.000Z",
    "updatedAt": "2026-09-04T12:00:00.000Z"
  }
}
```

#### GET /api/v1/orders/:id
**Purpose:** View order details (Includes buyer, artisan, and product nested data).
**Authentication:** Required
**Role:** Buyer/Artisan belonging to the order.

#### PATCH /api/v1/orders/:id/accept
**Purpose:** Fully accept an order.
**Current Allowed Status:** `PENDING`
**Authentication:** Required
**Role:** ARTISAN (Must own order)
**Resulting Status:** `ACCEPTED`

#### PATCH /api/v1/orders/:id/partial
**Purpose:** Partially accept an order.
**Current Allowed Status:** `PENDING`
**Authentication:** Required
**Role:** ARTISAN (Must own order)
**Request Body:**
```json
{
  "acceptedQty": 60
}
```
**Resulting Status:** `PARTIALLY_ACCEPTED`

#### PATCH /api/v1/orders/:id/reject
**Purpose:** Reject an order.
**Current Allowed Status:** `PENDING`
**Authentication:** Required
**Role:** ARTISAN (Must own order)
**Resulting Status:** `REJECTED`

#### PATCH /api/v1/orders/:id/fulfilling
**Purpose:** Move order to fulfillment stage.
**Current Allowed Status:** `ACCEPTED` or `PARTIALLY_ACCEPTED`
**Authentication:** Required
**Role:** ARTISAN (Must own order)
**Resulting Status:** `FULFILLING`

#### PATCH /api/v1/orders/:id/complete
**Purpose:** Mark order as completely fulfilled.
**Current Allowed Status:** `FULFILLING`
**Authentication:** Required
**Role:** ARTISAN (Must own order)
**Resulting Status:** `COMPLETED`

## 9. Flutter Error-Handling Guidance

The backend universally utilizes a standard error structure. Flutter should parse HTTP 400, 401, 403, and 404 status codes.

**Standard Error Response:**
```json
{
  "success": false,
  "message": "Validation error: Message is required",
  "stack": "..." // Only present in development mode
}
```

- **400 Bad Request:** Usually Zod validation errors. Extract `message` for the user.
- **401 Unauthorized:** Token is missing or invalid. Flutter must route to the Login Screen.
- **403 Forbidden:** The user is logged in, but their `role` (e.g., BUYER vs ARTISAN) restricts them, or they don't own the resource.
- **404 Not Found:** Resource ID doesn't exist.
- **413 Payload Too Large:** Specifically for `/api/v1/ai/speech-to-text` when audio exceeds 25 MB.
